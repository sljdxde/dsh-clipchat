## 逐条

### #1 界面与原型不一致（严重）

- **现象**：滑词并点「问这段」后，卡片与 v2 原型不一致。
- **证据**：现场卡片见上；原型首屏要素见票 03「选段预览、4 个快问、输入框、回答区、token 行、留痕/带回主线」。
- **根因**：spec §8 把原型简化成「顶部选段预览 / 中间问答 / 底部输入与操作」，实现票 12/13/19 照 spec 拆分，原型里的快问、问答线程、footer token 行在拆票时丢失。**不是渲染 bug，也不是 bundle 未更新。**
- **重复检查**：无现成实现；与 #2、#3 部分重叠。
- **建议**：拆成 1a = #3、1b = #2、1c = 卡片形态与视觉。1c 需先定范围，因为原型里有两项不在 M1 spec：
  - 「前文 2 轮 / 仅选段」上下文切换（spec §5 是固定口径）
  - 「本会话高亮 N」列表（spec §9 是留痕列表）
- **1c 选项**：
  - A. 只补形态（选段栏、快问、线程、footer、样式），不带上面两项 —— 最小，建议默认。
  - B. 全量对齐原型 —— 工作量最大，还要改 spec。
  - C. 只补问答线程 + 快问，其余留 M1.1 —— 折中。

### #2 提问后不自动高亮

- **现象**：提问结束后原文没有高亮，必须手动点「高亮这段」。
- **证据**：`send()` 只发 SSE，不写高亮；`addHighlight` 仅由「高亮这段」按钮触发。票 03 Answer 明确「提问或点『高亮这段』才提交」，spec §8 写成「『高亮这段』在首次提交时写入」，被实现理解为仅按钮提交。
- **影响**：用户问完回头找不到锚点；与原型「高亮挂问答线程」的模型不一致。
- **方向**：首问发送成功（或发送时）为当前选段提交一次高亮，已存在则跳过；仍保持「意外划词不落盘」。
- **待定**：提交时机取「发送时」（原型语义、乐观）还是「首帧成功后」（失败不留）。推荐发送时。

### #3 缺快捷提问

- **现象**：卡片输入框上方没有原型里的快问。
- **证据**：原型 `PRESETS` 4 条：解释这段 / 翻译 / 找问题 / 举个例子；client 无对应常量与渲染。票 03 首屏要素明确包含「4 个快问」，实现票 13 未带。
- **方向**：输入框上方 4 个 chip，点击即用该问题发送；文案走 locale；流式中禁用。
- **备注**：反馈原文第 3 条的「期望」是从第 2 条复制的，按「补齐快问」理解。

## Agent Brief（#3 草稿）

**Category:** bug
**Summary:** 卡片补回原型确认过的 4 个快捷提问。

**Current behavior:** 卡片只有输入框，没有快问；原型基线与票 03 都要求首屏有 4 个快问。

**Desired behavior:** 卡片输入框上方渲染 4 个 chip（解释这段 / 翻译 / 找问题 / 举个例子）。点击后以该问题文本走现有提问路径（同一流式、同一历史、同一 token 行），不额外弹窗。流式中或选段为空时禁用。中英文文案随 DSH 语言切换。

**Key interfaces:**
- 卡片渲染函数新增 preset 列表，条目形如 `{ id, question }`，问题文本进入现有 `ask`/`send` 路径。
- 复用现有 locale 命名空间，新增 4 条文案；不新建命名空间。

**Acceptance criteria:**
- [ ] 打开卡片时 4 个 chip 可见，顺序为 解释这段、翻译、找问题、举个例子。
- [ ] 点击 chip → 以对应问题发送，流式回答、token 行正常，事后可继续追问。
- [ ] 流式期间 chip 禁用；结束后恢复。
- [ ] 中文界面显示中文 chip，英文界面显示英文 chip。
- [ ] `npm run check` 通过，且新增用例覆盖「点 chip 发送对应问题」。

**Out of scope:**
- 快问可配置 / 设置页（M2）。
- #2 的自动高亮。
- 卡片整体视觉改造（#1c）。

## Agent Brief（#2 草稿）

**Category:** bug
**Summary:** 首次提问即为当前选段提交高亮，不再要求手动点「高亮这段」。

**Current behavior:** 提问只走 SSE；高亮仅由按钮提交。用户问完看不到锚点。

**Desired behavior:** 当前选段尚无高亮时，首次提问（发送时）自动提交并持久化该高亮；按钮随后显示「取消高亮」。划词后直接关闭卡片不产生高亮。提问失败也不回滚已提交的高亮，但不允许重复提交同一选段。

**Key interfaces:**
- 提问入口在发起 SSE 前检查 `hasHighlight(nodeKey, selection)`，缺失则调用现有高亮提交路径并 `persistHighlight('add', ...)`。
- 高亮状态与按钮文案沿用现有 `highlighted` 语义。

**Acceptance criteria:**
- [ ] 划词 → 直接问 → 原文出现高亮，刷新后仍在。
- [ ] 划词 → 不提问直接关闭 → 无高亮、无存储写入。
- [ ] 同一选段连续追问不重复生成高亮。
- [ ] 提问后按钮显示「取消高亮」，点击可删除并同步存储。
- [ ] `npm run check` 通过，新用例覆盖「提问自动高亮」与「关闭不留痕」。

**Out of scope:**
- 快问（#3）。
- 高亮渲染外观已按 ADR 0005 改为绿色底线；不在 #1/#2/#3 的范围内。
- 自动高亮由 AI 判断（已在需求文档 Out of Scope）。

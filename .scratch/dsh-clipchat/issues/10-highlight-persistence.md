# 10 划词高亮的持久化与生命周期

Type: grilling
Status: resolved
Blocked by: 02

## Question

2026-11-16 新需求：划词的位置在当前 session 内要持久保留（类似公众号文章划线）；归档或删除会话后同步清理；后台存储默认保留 7 天。需要裁定：

1. **「永久」与 7 天 TTL 的关系**：7 天无访问才清理（推荐，兼顾持久感与磁盘），还是从创建起 7 天？UI 是否显示倒计时？
2. **归档的语义**：归档 = 立即清理（取消归档不恢复），还是仅「删除会话」才清理？归档是可逆操作，但当前需求说同步清理。
3. **触发方式**：每次划词都自动高亮并持久化，还是划词后点「高亮」才持久（微信式）？自动会误伤复制/双击选词。
4. **锚点模型**：messageId + 字符偏移（推荐），还是 DOM 路径？跨段落、代码块、分页窗口（未加载的消息）如何重锚定？
5. **存储位置**：host 的 JSON/SQLite（可被会话清理钩子触发、跨刷新）还是浏览器 localStorage（简单，只在本机）？host 侧已确认有 `workspace/session-archived` 事件可挂。
6. **问答与高亮的关系**：问答默认随高亮保存，还是仍需「留痕」才保存？v2 原型当前是后者。

## Answer

（2026-11-16 定稿）

1. **存储**：host JSON，`~/.dsh/clipchat/<sessionId>.json`；host 半读写，客户端走路由。原子写（临时文件 + rename），文件带 `version`。不用 localStorage。
2. **TTL**：7 天**无访问**才清理；读取列表、新增高亮、提问都续期。界面不显示倒计时。清理时机：插件启动 + 每次读取时惰性清理过期文件。
3. **归档**：**不清理**，取消归档后可恢复。只有**永久删除会话**才清理。当前只有 `workspace/session-archived` / `session-unarchiving` 事件，没有删除事件，所以删除清理用**孤儿清理**：启动/读取时对比当前会话集合，删掉找不到会话的文件；07 再核验归档管理器的删除路径。
4. **触发**：划词只弹卡片；点「高亮这段」或提问才落盘。意外划词不产生记录。
5. **锚点**：`messageId`（chat node key）+ 文本块序号 + 块内字符偏移 + 选段文本（校验用）。渲染时按锚点重标；失败则用选段文本前缀在该消息内搜索。分页未加载的消息不渲染，滚到再标。
6. **问答与高亮**：问答默认只在内存，点「留痕」才随高亮落盘；高亮本身在显式提交后即持久化。

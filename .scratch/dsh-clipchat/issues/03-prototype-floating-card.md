# 03 就近浮窗卡片的粗原型

Type: prototype
Status: resolved
Blocked by: 09

## Question

浮窗卡片的信息层级与三态（空 / 流式 / 完成 / 错误）如何排布，才能让用户 3 秒内知道先点哪、答案在哪、怎么追问？

需要覆盖：

- 卡片宽度、最大高度、内部滚动；与宿主外层描边/阴影的关系（宿主 wrapper 已提供外框，别再叠一层）。
- 首屏元素顺序：选段预览（可折叠）、4 个快问、输入框、回答区、token 行、「留痕」「带回主线」。
- 连续追问时卡片是固定高度滚动，还是随内容增长到上限再滚动。
- 空态与错误态（无模型、鉴权失败、超时、用户停止）。
- 窄屏降级只需给出一句话策略，不在本 ticket 展开。

## 产物

交互原型：[floating-card.html](../prototype/floating-card.html)（单文件，双击打开；`?variant=A|B|C`，默认 A）。

2026-11-16 用户反馈：倾向 **A（紧凑气泡）**，要求可交互。当前已支持：

- 正文划选任意文字 → 浮窗换锚点（模拟宿主划词）
- 4 个快问 / 输入 Enter → 模拟流式回答；可连续追问
- 「前文 2 轮 / 仅选段」上下文档位切换，footer 的 ctx 估算随之变化
- 留痕（按钮变「已留痕 ✓」，selbar 出现「本会话留痕 N」；点进去是本会话列表：展开 / 插入输入框 / 删除；当前选段的记录带「当前选段」标签；B 的留痕 tab 是同一数据的侧栏形态）
- 带回主线（引用 + 摘要插入底部主输入框）
- × / Esc 关闭；点高亮文字或重新划选重开
- 场景：正常 / 长回答 / 慢速 / 报错（含重试）

仍待 09：宿主 text-interaction 实跑后再定稿；当前是**模拟流式，不调模型**。

## v2（2026-11-16 新需求）

需求：划词位置在当前 session 内持久保留（类似公众号划线），归档/删除会话同步清理，后台存储默认 7 天。

原型：[session-highlights.html](../prototype/session-highlights.html)（单文件；localStorage 持久化；刷新后重锚定并重绘）。

已演示：划词只弹卡片（不落盘）并自动聚焦输入框，提问或点「高亮这段」才提交；仅 assistant 正文可划；刷新后恢复；每个高亮挂独立问答线程；点「留痕」才保存问答；卡片底部可选模型（默认跟随主会话，选择随高亮保存）；会话菜单归档/删除/模拟 7 天后；TTL 倒计时。关闭路径：点卡片外空白 / Esc / ×；点高亮本身是切换，不关闭。

仍待票 10 裁定：TTL 语义（无访问 7 天 vs 创建起 7 天）、归档是否可逆、自动高亮 vs 点选高亮、锚点模型、host 存储 vs localStorage。

## Answer

2026-11-16 用户确认 v2 形态。定稿要点：

- 划词只弹卡片、自动聚焦输入框；提问或点「高亮这段」才提交，意外划词不留痕。
- 仅 assistant 正文可划；关闭 = 点空白 / Esc / ×；点已有高亮是切换，不关闭。
- 卡片底部可选模型（跟随主会话 / deepseek-flash / deepseek-v4-pro），随该高亮保存，下一次提问生效。
- 高亮刷新后恢复；归档/删除/7 天 TTL 在原型里可演示。
- v2 作为 M1 交互基线；技术路径仍由 09 验证（形态不随 09 结果改变，只可能换承载方式）。

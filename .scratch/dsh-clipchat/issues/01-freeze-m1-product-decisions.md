# 01 冻结 M1 产品口径

Type: grilling
Status: resolved
Blocked by: —

## Question

在需求文档 v1.0 基础上，M1 的产品边界、默认口径与验收冲突如何裁定？具体需要回答：交付物边界、M1 是否含连续追问、默认上下文档位、可划选的内容范围、留痕与刷新恢复的语义、模型与成本展示、「带回主线」插入什么。

## Answer

2026-11-16 与 lead 的 charting grilling 中确认：

1. 交付物：冻结的 M1 技术方案 + M2/M3 路线；不写 M2/M3 细节，也不跳过方案直接开工。
2. M1 包含浮窗内连续追问；实现上把本窗问答历史压进同一次 `ctx.llm.stream` 请求。
3. 默认上下文：选段 + 所在整条 assistant 消息 + 主线最近 2-3 轮；「只带选段」不再作为默认，留作后续降档开关。
4. 仅 assistant 正文划选触发；用户消息与思考区不弹窗。
5. 浮窗关即弃；只有用户点「留痕」的记录写入本地持久化，刷新可恢复。验收 3 的口径改为「留痕记录可恢复」，不是「浮窗对话可恢复」。
6. 模型跟随主会话当前模型；浮窗显示输入/输出 token。
7. 「带回主线」插入：选段引用（复用宿主 quote）+ 问答摘要（问题 + 答案要点），一起进输入框。

同时裁定需求文档中的错误与冲突：

- 「一次性隐藏会话」不成立：改用 host 半 + webServer 路由 + `ctx.llm.stream`，不建 session。
- 浮窗定位由宿主负责，M1 不自建定位。
- 连续追问从 M2 提到 M1。
- 竞品表更正：bubble-explain 已支持递归追问，select-ask 已做划词一次性提问。
- 「第二选段拼入」改为待重新设计（见地图 Not yet specified）。
- 兼容基线改为 0.2.2-rc.3。
